# Резервное копирование и восстановление

Согласно ТЗ §10.3, встроенных средств резервного копирования в приложении нет. Хранение резервных копий, периодичность и процедуры восстановления обеспечиваются хостинг-провайдером или облачной платформой, на которой развёрнут маркетплейс.

## Что нужно бэкапить на стороне инфраструктуры

| Компонент | Содержание | Критичность |
|---|---|---|
| База данных | Пользователи, компании, каталог, заказы, журналы аудита | Высокая |
| Файловое хранилище | Загрузки (логотипы, документы, изображения товаров) — диск `local`/`public` или S3 | Высокая |
| Конфигурация | Файл `.env` на сервере (секреты, не хранить в git) | Высокая |
| Код | Репозиторий Git / артефакты деплоя | Средняя (восстанавливается из VCS) |

## Рекомендуемый регламент (хостинг)

1. **Периодичность:** ежедневный полный снимок БД; инкрементальные бэкапы по политике провайдера (не реже 1 раза в сутки для production).
2. **Хранение:** копии вне рабочего инстанса (отдельный регион/бакет), срок хранения — по политике заказчика (рекомендуется не менее 7–30 дней).
3. **Проверка:** периодический тестовый restore на staging (не реже 1 раза в квартал).
4. **Шифрование:** на стороне провайдера / at-rest encryption дисков и бэкапов.

## Восстановление

1. Зафиксировать инцидент и момент «точки восстановления» (timestamp).
2. Восстановить БД средствами панели хостинга / `mysqldump`/`pg_restore` / snapshot managed DB.
3. Восстановить файлы `storage/` (или объектное хранилище) на ту же точку.
4. Проверить `.env` (`APP_KEY` должен совпадать с исходным — иначе не расшифруются encrypted-значения и сессии).
5. Выполнить `php artisan migrate --force` только если схема после бэкапа отстаёт; не запускать destructive-команды без необходимости.
6. Проверить вход, критичные разделы и журнал аудита.

Конкретные команды и SLA зависят от выбранного хостинга и фиксируются в договоре обслуживания (SLA) с провайдером.

## HTTPS и сессии на production

- `APP_ENV=production`, `APP_URL=https://...`
- Приложение форсирует схему HTTPS (`URL::forceScheme`)
- `SESSION_SECURE_COOKIE=true` (или не задавать — в production включается по умолчанию)
- Reverse-proxy: доверяются `X-Forwarded-*` (`trustProxies`)
